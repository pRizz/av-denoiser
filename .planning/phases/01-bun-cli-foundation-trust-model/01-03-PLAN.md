<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tool discovery -> operating system | The CLI locates executables on PATH and runs version commands. |
| Process runner -> external executable | Project code invokes external media tools through `Bun.spawn`. |
| Discovery facts -> later CLI rendering | Local paths, versions, and capability statuses become structured diagnostics. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-08 | Tampering / Elevation of Privilege | `src/adapters/process-runner.ts` | mitigate | Use `Bun.spawn([command.executable, ...command.args])` only; test and grep for absence of `shell: true` and `exec(`. |
| T-01-09 | Spoofing | `src/adapters/tool-discovery.ts` | mitigate | Use `Bun.which` and include resolved executable paths in doctor facts so users can see which binary was checked. |
| T-01-10 | Repudiation | `src/adapters/tool-discovery.ts` | mitigate | Emit explicit `not-checked-yet` capability statuses so PATH/version checks are not misrepresented as full capability validation. |
| T-01-11 | Information Disclosure | `src/adapters/tool-discovery.ts` | mitigate | Capture concise version/probe facts only; do not store full environment variables or unbounded stderr in doctor facts. |
| T-01-12 | Denial of Service | `src/adapters/process-runner.ts` | mitigate | Support `timeoutMs` in `ProcessCommand` and use a bounded version-probe timeout for doctor checks. |
